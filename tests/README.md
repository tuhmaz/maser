# الاختبارات

راجع [`docs/acceptance-criteria.md`](../docs/acceptance-criteria.md) و[`docs/security-requirements.md`](../docs/security-requirements.md) للقائمة الكاملة المطلوبة.

## أين تعيش الاختبارات

- **اختبارات وحدات Go**: بجانب الكود مباشرة داخل `services/api/internal/**/*_test.go` و`services/worker` (مثال: `services/api/internal/utils/password_test.go`).
- **اختبارات تكامل API**: `tests/api/` — تشغّل خادم API فعلي ضد قاعدة بيانات اختبار، وتغطي: المصادقة والجلسات، الصلاحيات (RBAC)، تجاوز الصلاحيات (IDOR)، تسليم المحاولات، Idempotency.
- **اختبارات الواجهة**: `tests/web/` — تدفقات المستخدم الحرجة (تسجيل، دخول، اختيار الصف/المادة، حل اختبار).
- **اختبارات شاملة (e2e)**: `tests/e2e/` — تدفق كامل عابر للخدمات (Web → API → DB) يحاكي رحلة الطالب الأولى في `docs/user-journeys.md`.

## أولوية البناء (قبل أي نشر تجريبي)

1. المصادقة والجلسات (`docs/security-requirements.md` → "اختبارات الأمان الإلزامية")
2. صحة المحتوى (كل سؤال له إجابة صحيحة، كل سؤال مرتبط بمهارة، ...)
3. محرك الاختبارات (لا تعتمد النتيجة على الواجهة، حفظ تدريجي، استئناف بعد انقطاع)
4. الأداء الأساسي (الصفحة الرئيسية، لوحة الطالب، تحميل الاختبار)

لا يُعتبر أي مسار "جاهزًا" في `docs/acceptance-criteria.md` قبل تغطيته هنا.
