# معايير قبول النسخة التجريبية (MVP)

تُعتبر النسخة جاهزة للتجربة الحقيقية عندما تتحقق كل النقاط التالية:

- [ ] يمكن للطالب إنشاء حساب
- [ ] تبقى جلسة الدخول مستقرة (لا تنقطع عشوائيًا)
- [ ] يستطيع الطالب اختيار الصف والمادة
- [ ] يستطيع تنفيذ الاختبار التشخيصي كاملًا
- [ ] تظهر نتيجة مفهومة (وليست رقمًا غامضًا)
- [ ] تُنشأ مهمة يومية تلقائيًا بعد الاختبار التشخيصي
- [ ] يستطيع الطالب حل اختبار درس
- [ ] تُحفظ الإجابات بعد كل سؤال (وليس فقط عند التسليم)
- [ ] تظهر الأخطاء في دفتر الأخطاء تلقائيًا
- [ ] تُعاد جدولة الأخطاء وفق دورة المراجعة المحددة
- [ ] يظهر تقدم المهارات في لوحة الطالب
- [ ] تستطيع الإدارة إنشاء سؤال، مراجعته، ونشره عبر دورة الحياة الكاملة
- [ ] توجد تحليلات فعلية للأحداث الرئيسية (وليست فقط مسجلة دون استخدام)
- [ ] تعمل المنصة بشكل سليم على الهاتف (Mobile First تم التحقق منه)
- [ ] يمكن أخذ نسخة احتياطية من قاعدة البيانات واستعادتها فعليًا
- [ ] لا يمكن لأي طالب الوصول إلى بيانات طالب آخر (تم اختباره أمنيًا)
- [ ] يمكن إيقاف أي ميزة عبر Feature Flag دون نشر جديد

## القرارات المثبَّتة قبل كتابة الكود

هذه القرارات ثابتة ولا تُفتح للنقاش أثناء البرمجة إلا بقرار صريح موثّق:

1. اسم "Alemedu" مؤقت
2. `alemedu.com` للواجهة
3. `api.alemedu.com` للـ API
4. `admin.alemedu.com` للإدارة
5. الصف السابع / الرياضيات / الأردن كنطاق تجريبي
6. PostgreSQL لقاعدة البيانات
7. Go لخدمة الـ API
8. Next.js للواجهة والإدارة
9. بنية Monorepo
10. تسجيل مستقل تمامًا عن موقع الإيمان في البداية
11. OpenAPI كمرجع رسمي وحيد للواجهات
12. دورة مراجعة بشرية إلزامية للمحتوى قبل النشر
13. عدم إضافة الدفع أو تطبيق الهاتف في النسخة الأولى
14. التحليلات تُبنى من أول إصدار (وليست إضافة لاحقة)
15. فصل تام عن قاعدة بيانات موقع الإيمان

## القرار النهائي (الفلسفة الحاكمة للمشروع)

يُبنى Alemedu كمنتج مستقل بالكامل على `alemedu.com` / `api.alemedu.com` / `admin.alemedu.com`. يُستخدم موقع الإيمان فقط من أجل: الإعلان، توجيه الطلاب، اختبار الإقبال، نقل الزائر إلى النشاط المناسب، وبناء أول قاعدة مستخدمين.

**لا يبدأ المشروع بمحاولة خدمة جميع الطلاب من الصف الخامس إلى التوجيهي مرة واحدة.** يبدأ بنسخة محدودة تثبت ثلاث نقاط فقط:

1. هل يكمل الطالب الاختبار؟
2. هل يفهم تقريره؟
3. هل يعود لتنفيذ مهمة أخرى ومراجعة أخطائه؟

عند نجاح هذه النقاط الثلاث، يكون التوسع لبقية الصفوف والمواد قرارًا مبنيًا على بيانات فعلية، وليس افتراضًا.
